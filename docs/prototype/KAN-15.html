5介面草稿

class RawJob(BaseModel):
    """來源回傳的原始資料，一個欄位都不解讀。"""
    source: str
    source_job_id: str
    url: str
    payload: dict[str, Any]        # 原封不動落進 jobs.jd_raw

class JobPosting(BaseModel):
    """正規化後的統一形狀，欄位對齊 jobs 表。"""
    source: str
    source_job_id: str
    url: str
    title: str
    company_name: str
    jd_text: str
    salary_min: int | None = None
    salary_max: int | None = None
    salary_type: Literal["monthly", "annual", "negotiable"] | None = None
    location: str | None = None
    remote_policy: Literal["remote", "hybrid", "onsite"] | None = None
    raw: dict[str, Any]

    @property
    def content_hash(self) -> str:
        return hashlib.sha256(self.jd_text.encode()).hexdigest()

class SourceAdapter(Protocol):
    source: ClassVar[str]
    async def search(self, query: SearchQuery) -> list[RawJob]: ...
    def normalize(self, raw: RawJob) -> JobPosting: ...
search 是 async（打網路、要限速），normalize 是同步純函式 —— 沒有 I/O，所以測試不需要任何 mock。這是刻意的切法：把「難測的部分」壓縮到最小。

6測試策略

測：

  • normalize() 邊界 —— 薪資寫法（"$50k - $70k" / 面議 / 空值）、缺欄位、JD 夾雜 HTML、超長文字
  • 去重 —— 同批出現兩次相同 url、跨批次重跑不重複插入
  • content_hash —— JD 沒變時只動 last_seen_at，其他欄位不覆蓋
  • crawl_runs —— 成功時三個計數正確；中途拋例外時狀態變 failed 而非留在 running

怎麼測：fixture 是一份真實回應存成 JSON（抓一次、存下來、之後永遠離線讀）。HTTP 層用 httpx.MockTransport 換掉 —— 不打真實網站，CI 也能跑。

不測：真實網路請求、限速的實際等待時間（改測「limiter 有被呼叫」而不是測它真的睡了一秒）。
